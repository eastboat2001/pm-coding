# PRD 文档（中国象棋单机对战版）

## 1. 文档信息

- **项目名称**：中国象棋单机对战 Demo
- **需求名称**：中国象棋单机对战版需求规格说明

## 2. 需求背景

### 2.1 背景说明
当前市场上缺乏轻量级、无需联网且支持完整规则校验与视频化复盘功能的中国象棋 Demo。本项目旨在为本地同屏对弈的玩家提供一个简单、规范且具备对局记录能力的工具。

### 2.2 需求目标
- 实现严格的中国象棋行棋规则校验。
- 支持本地双人同屏对弈及手动提和功能。
- 自动记录对局棋谱，并提供具备进度控制的视频化回放功能。

## 3. 需求范围

### 3.1 本次范围
- **单机双人对战**：支持两名玩家在同一台电脑上轮流操作。
- **规则校验**：包括马走日、象飞田、九宫格限制、过河限制、炮隔子打子等。
- **胜负判定**：以手动吃掉对方“将/帅”为准。
- **提和功能**：支持玩家一键提和，立即结束对局。
- **数据持久化**：自动保存对局时间、步数、获胜方及完整棋谱。
- **历史回放**：提供历史列表，支持带进度条、倍速调节的自动回放。

### 3.2 非本次范围
- 不涉及联网对战功能。
- 不涉及 AI 人机对战算法。
- **不提供悔棋功能**。
- 不涉及棋盘随回合自动旋转。
- **不进行“将军”或“自杀性行棋”的强制拦截**（允许玩家走位导致老将被吃）。

## 4. 用户与使用场景

### 4.1 目标用户
- 线下同处一地的象棋爱好者。
- 需要对对局进行复盘研究的玩家。

### 4.2 核心使用场景
1. **同屏对弈**：两名玩家共用一台电脑，系统根据规则校验每一步行棋，直到一方吃掉对方老将或提和。
2. **对局存档**：对局结束后，系统无需用户干预，自动将过程存入本地数据库。
3. **视频复盘**：用户在历史列表中找到某场对局，像看视频一样观看系统自动演示行棋过程。

## 5. 功能需求

### 5.1 功能概述
系统采用本地 Web 应用架构（C# 后端 + SQLite + 原生 JS 前端），实现从对弈到存档再到回放的完整闭环。

### 5.2 功能点明细

#### 功能点 1：行棋规则校验
- **功能描述**：在对弈过程中，严格限制棋子的移动路径和区域。
- **触发方式**：玩家点击棋子并尝试移动到目标位置。
- **处理逻辑**：
    - 校验棋子特有路径（如马走日、炮隔子打）。
    - 校验区域限制（如士/将不出九宫，象不过河）。
    - 校验障碍物（如蹩马腿、塞象眼）。
- **输入项**：起始坐标、终点坐标。
- **输出结果**：合法则移动棋子；不合法则拦截并提示。
- **异常情况**：尝试移动对方棋子时系统不予响应。

#### 功能点 2：胜负与提和判定
- **功能描述**：判定对局何时结束及结果归属。
- **触发方式**：手动吃掉老将或点击“提和”按钮。
- **处理逻辑**：
    - 若目标位置为对方“将/帅”，移动后立即宣告胜利。
    - 若点击“提和”，系统直接判定为和局，无需对方确认。
- **输入项**：行棋动作或提和指令。
- **输出结果**：弹出对局结果弹窗，停止棋盘交互。

#### 功能点 3：视频化回放系统
- **功能描述**：自动重现历史对局过程。
- **触发方式**：从历史列表页点击进入。
- **处理逻辑**：
    - 按棋谱步序自动执行移动动画。
    - 支持 0.5x、1.0x、2.0x 倍速切换。
    - 支持随时暂停/继续。
- **输入项**：播放控制指令、倍速选择、进度条拖动。
- **输出结果**：棋盘动态演示。

## 6. 业务规则
- **先行权**：默认红方先行。
- **自杀性行棋**：系统**不拦截**导致自己被将军的走法，也不强制玩家“应将”。
- **落子无悔**：一旦完成一次合法行棋，立即切换回合，不支持撤销。
- **自动存档**：对局结束（胜负或和局）时，系统必须自动保存数据，不得丢失。

## 7. 页面 / 交互说明

### 7.1 页面说明
- **对弈主页面**：包含标准棋盘、当前回合状态显示、“提和”按钮、历史记录入口。
- **历史列表页**：展示对局日期、总步数、获胜方（红胜/黑胜/和局）。
- **回放页面**：包含棋盘、播放/暂停控制、倍速选择器、步数进度条。

### 7.2 交互流程
1. 进入应用 -> 点击开始对弈。
2. 轮流行棋 -> 触发吃将或提和。
3. 系统弹窗提示结果 -> 自动保存并返回主页。
4. 点击历史记录 -> 选择对局 -> 进入回放页观看。

## 8. 文案说明
- **状态提示**：请红方行棋 / 请黑方行棋。
- **结果提示**：红方胜 / 黑方胜 / 和局。
- **按钮文案**：提和、查看历史、播放、暂停、倍速 (0.5x/1.0x/2.0x)。

## 9. 数据与依赖
- **后端依赖**：依赖 C# (ASP.NET Core / Minimal API) 处理业务逻辑与数据存储。
- **数据库**：使用 SQLite 存储 `Games`（对局概况）和 `Moves`（行棋明细）表。
- **前端依赖**：原生 HTML/CSS/JS，不依赖外部重型框架。
- **环境依赖**：运行环境需安装 .NET 运行时。

## 10. 风险与注意事项
- **规则风险**：由于不拦截“自杀性行棋”，玩家可能因误操作导致老将被吃，需在 UI 层面给予适当的规则说明。
- **部署风险**：作为本地 Web 应用，需确保后端服务启动后，浏览器能正常跨域访问（若前后端分离部署）。

## 11. 验收标准
- **规则准确性**：马、象、炮、兵等所有棋子的特殊走法及限制必须 100% 符合中国象棋基本规则。
- **判定准确性**：吃掉老将或点击提和后，系统能准确记录获胜方并停止对局。
- **数据完整性**：每局结束后的棋谱必须完整保存，回放时不能出现跳步或坐标偏移。
- **回放控制**：倍速切换需有明显的语速变化，进度条拖动需能准确跳转到对应步数。

## 12. 开放性问题
- **无**（当前所有核心逻辑已在沟通中确认）。
