# PRD 文档（草案）

> **说明**：本文档基于已采集的需求信息生成。当前需求采集覆盖率为 100%，部分细节（如页面具体样式、交互细节）基于 PC 端使用习惯进行了合理假设，并在文中明确标注。

## 1. 文档信息

- **项目名称**：个人记账系统
- **需求名称**：个人日常消费记账系统需求规格说明书

## 2. 需求背景

### 2.1 背景说明

用户需要一个轻量、私有的本地记账工具，用于追踪日常的个人收入与支出情况，以替代复杂的商业记账软件或简单的纸笔记录。

### 2.2 需求目标

- 实现手动记录每日收支明细。
- 支持自定义账务分类和支付方式标签。
- 提供按月份和分类的筛选能力，并实时汇总收支结余。
- 保证数据的私密性（本地运行）。

## 3. 需求范围

### 3.1 本次范围

- **收支记录管理**：支持记录的增、删、改、查（CRUD）。
- **配置管理**：自定义收支分类（一级平铺）和支付方式标签。
- **筛选与统计**：支持按“月份”和“分类”筛选，实时计算总收入、总支出和结余。
- **本地化运行**：适配电脑浏览器，使用 Vue + Flask + SQLite 架构。

### 3.2 非本次范围

- 不涉及账户余额自动对账（仅作标签记录）。
- 不涉及复杂的统计图表（如饼图、折线图）。
- 不涉及用户登录、注册及多用户权限系统。
- 不涉及数据导出（Excel/CSV）或第三方账单（支付宝/微信）导入。
- 不涉及图片、附件上传及多币种支持。

## 4. 用户与使用场景

### 4.1 目标用户

- 追求数据私密性、习惯在电脑端进行财务整理的个人用户。

### 4.2 核心使用场景

1. **每日记账**：用户在电脑上打开系统，录入当天的消费或收入，选择对应的分类和支付方式。
2. **财务回顾**：用户通过切换月份，查看当月的收支明细，并根据顶部的汇总数据了解当月结余。
3. **分类调整**：用户根据消费习惯的变化，新增或修改消费分类名称。

## 5. 功能需求

### 5.1 功能概述

系统提供纯手动的收支记录管理功能，支持基于收支类型的分类隔离逻辑，并能根据筛选条件实时联动统计数值。

### 5.2 功能点明细

#### 功能点 1：收支记录管理

- **功能描述**：对账目明细进行维护。
- **触发方式**：点击“新增”按钮或点击已有记录行的“编辑/删除”图标。
- **处理逻辑**：
  - 账目类型（收入/支出）必填。
  - 金额支持两位小数，必填。
  - 日期精确到天，默认填充当天，必填。
  - 分类与支付方式为选填。
  - 列表默认按“日期”倒序排列。
- **输入项**：类型、金额、日期、分类、支付方式、备注。
- **输出结果**：历史记录列表更新。
- **异常情况**：未填写必填项时，系统提示“请完善必填信息”。

#### 功能点 2：配置项管理

- **功能描述**：管理分类和支付方式。
- **触发方式**：进入配置管理页面。
- **处理逻辑**：
  - 分类需标记为“收入类”或“支出类”。
  - **引用保护**：若分类或支付方式已被账目引用，禁止删除。
- **输入项**：名称、所属类型（仅限分类）。
- **输出结果**：配置列表更新。
- **异常情况**：删除已被引用的项时，提示“该分类/支付方式已被使用，无法删除”。

#### 功能点 3：筛选与汇总统计

- **功能描述**：根据条件过滤数据并计算总额。
- **触发方式**：切换月份下拉框或分类下拉框。
- **处理逻辑**：
  - 默认展示“全部”记录。
  - 汇总金额（总收入、总支出、结余）= 当前筛选结果下的数据累加。
- **输入项**：月份（YYYY-MM）、分类。
- **输出结果**：过滤后的列表及实时更新的统计数值。

## 6. 业务规则

- **收支分类隔离**：录入时，若选择“支出”，分类下拉框仅显示支出类分类；反之亦然。
- **引用保护规则**：已在账目中使用的分类或支付方式不可删除。
- **排序规则**：历史列表统一按日期字段倒序排列，不提供手动调序。
- **数据精度**：金额字段强制保留两位小数。
- **必填项规则**：账目类型、金额、日期为必填；分类、支付方式、备注可留空。

## 7. 页面 / 交互说明

### 7.1 页面说明

- **主列表页**：
  - **入口位置**：系统首页。
  - **页面元素**：月份筛选器、分类筛选器、汇总统计栏（总收/总支/结余）、历史记录长列表（滚动查看）、新增按钮。
- **配置管理页**：
  - **入口位置**：假设位于页面顶部或侧边的“设置”导航（**假设**）。
  - **页面元素**：分类管理列表（区分收支）、支付方式管理列表、添加按钮。

### 7.2 交互流程

1. 用户进入首页，默认看到全部历史记录。
2. 用户选择“2023-10”月份，列表自动刷新，顶部统计栏同步更新为该月数值。
3. 用户点击“新增”，在弹窗（**假设**）中填写信息，点击提交，弹窗关闭，列表刷新。

## 8. 文案说明

- **统计文案**：总收入、总支出、结余。
- **提示文案**：
  - 删除拦截：“该分类已被使用，无法删除”。
  - 删除确认：“确认删除该笔记录吗？”。
  - 报错提示：“提交失败，请检查必填项”。

## 9. 数据与依赖

- **技术栈**：Vue (前端), Flask (后端), SQLite (数据库)。
- **部署**：本地环境运行，依赖本地 SQLite 数据库文件。

## 10. 风险与注意事项

- **数据备份**：由于是本地私有运行，数据安全性依赖于本地环境，建议用户定期手动备份 SQLite 数据库文件。
- **浏览器兼容性**：优先保证在主流现代浏览器（Chrome, Edge）上的显示效果。

## 11. 验收标准

- [ ] 能够成功记录一笔收支，且金额支持两位小数。
- [ ] 在历史列表中，账目按日期从近到远排列。
- [ ] 切换月份或分类筛选后，顶部的总收入、总支出和结余计算准确。
- [ ] 尝试删除一个已有账目关联的分类时，系统应报错拦截。
- [ ] 编辑或删除账目后，列表数据和汇总统计应立即同步更新。
