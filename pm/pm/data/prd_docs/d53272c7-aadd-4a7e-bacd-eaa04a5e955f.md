# PRD 文档模板（简洁版）

> **说明**：本需求已完成 100% 收集与确认，本文档为正式版 PRD，旨在指导 Vite + React 前端项目的开发实现。

## 1. 文档信息

- **项目名称**：个人项目管理看板 (Personal Project Kanban)
- **需求名称**：个人项目管理看板 MVP 基础功能需求

## 2. 需求背景

### 2.1 背景说明

用户在处理多个个人项目时，往往缺乏一个轻量级、直观且无需复杂配置的任务管理工具。现有的工具要么过于复杂（如 Jira），要么需要联网登录。本需求旨在创建一个纯前端运行、数据存储在本地、即开即用的看板工具。

### 2.2 需求目标

- **可视化管理**：通过看板直观展示任务的“待办、进行中、已完成”状态。
- **多项目统筹**：支持在单个项目视图与全局视图之间切换。
- **自动化提醒**：系统自动识别延期任务并提供视觉标记。
- **操作便捷性**：支持鼠标拖拽改变任务状态，并实现项目与任务的状态联动。

## 3. 需求范围

### 3.1 本次范围

- **技术框架**：基于 Vite + React 构建的纯前端 Web 应用。
- **数据存储**：使用浏览器 `localStorage` 进行本地持久化存储。
- **核心功能**：
  - 项目与任务的增删改查（CRUD）。
  - 拖拽式任务看板（支持跨列移动）。
  - 全局/单项目视图切换。
  - 统计概览（完成率、延期数等）。
  - 自动延期标记逻辑。
  - 演示数据初始化。

### 3.2 非本次范围

- 不涉及后端服务器及数据库。
- 不涉及用户登录、注册及多端同步。
- 不涉及文件上传或附件管理。
- 不涉及复杂的权限管理。

## 4. 用户与使用场景

### 4.1 目标用户

- 需要管理多个个人项目的独立开发者。
- 追求极简、本地化存储的个人用户。

### 4.2 核心使用场景

1. **项目初始化**：用户首次打开应用，系统自动加载演示数据，展示应用功能。
2. **任务流转**：用户在看板上通过拖拽，将任务从“待办”移动到“进行中”。
3. **全局复盘**：用户切换到“全局视图”，查看所有项目下已延期或紧急的任务。
4. **项目结项**：用户将项目状态改为“已完成”，系统自动将该项目下所有任务标记为完成。

## 5. 功能需求

### 5.1 功能概述

系统由项目管理、任务管理、看板交互和统计分析四个核心模块组成，所有数据通过 `localStorage` 实现刷新不丢失。

### 5.2 功能点明细

#### 功能点 1：项目管理

- **功能描述**：管理项目的基本信息及生命周期。
- **触发方式**：点击左侧项目列表的相关操作按钮。
- **处理逻辑**：
  - 支持创建、编辑、删除项目。
  - **联动规则**：若项目状态设为“已完成”，其下所有任务自动更新为“已完成”。
  - **级联删除**：删除项目时，同步删除其所属的所有任务。
- **输入项**：项目名称、描述、优先级（低/中/高）、截止日期、状态。
- **输出结果**：项目列表实时更新，关联任务状态同步。

#### 功能点 2：任务管理

- **功能描述**：管理具体执行项及其属性。
- **触发方式**：在看板或项目详情页点击创建/编辑。
- **处理逻辑**：
  - 支持任务 CRUD。
  - **延期判定**：系统根据“当前日期 > 截止日期”且“状态 != 已完成”自动触发“已延期”标记。
- **输入项**：标题、说明、负责人、优先级、截止日期、状态、标签。
- **输出结果**：看板卡片展示，延期任务带有明显视觉标识。

#### 功能点 3：看板交互

- **功能描述**：提供任务状态的可视化流转。
- **触发方式**：鼠标拖拽任务卡片或切换视图开关。
- **处理逻辑**：
  - 支持在“待办”、“进行中”、“已完成”三列间拖拽。
  - 支持“单项目视图”和“全局视图”切换。
- **输出结果**：任务状态属性实时变更并持久化。

#### 功能点 4：统计概览

- **功能描述**：展示整体进度数据。
- **处理逻辑**：自动计算项目总数、任务总数、已完成数、延期数及完成率。
- **输出结果**：右侧统计区域数值实时更新。

## 6. 业务规则

- **状态联动**：项目标记为“已完成”时，其下所有任务强制变更为“已完成”。
- **删除逻辑**：删除项目属于高危操作，需二次确认，并执行级联删除。
- **延期逻辑**：延期标记由系统实时计算得出，不可手动取消（除非修改截止日期或完成任务）。
- **持久化规则**：任何增删改操作后，必须立即同步至 `localStorage`。
- **初始化规则**：检测到 `localStorage` 为空时，自动注入预置的 JSON 演示数据。

## 7. 页面 / 交互说明

### 7.1 页面说明

- **页面名称**：主应用看板页
- **布局结构**：
  - **顶部标题区**：应用名称及全局操作按钮。
  - **左侧导航区**：项目列表，支持切换选中项目及创建新项目。
  - **中间看板区**：三栏式布局（待办、进行中、已完成），展示任务卡片。
  - **右侧面板区**：上方为统计卡片，下方为筛选面板（按优先级、标签、延期状态筛选）。

### 7.2 交互流程

1. 用户点击左侧项目列表中的某个项目。
2. 中间看板区域更新为该项目的任务。
3. 用户按住某个任务卡片，拖拽至另一状态列。
4. 系统更新该任务状态，并重新计算右侧统计数据。

## 8. 文案说明

- **状态标签**：待办、进行中、已完成、已延期。
- **优先级**：低、中、高。
- **统计项名称**：项目总数、任务总数、已完成任务、延期任务、完成率。
- **空状态提示**：暂无任务，请开始创建吧！

## 9. 数据与依赖

- **框架依赖**：React, Vite。
- **交互依赖**：`dnd-kit` 或 `react-beautiful-dnd`（用于实现拖拽）。
- **样式依赖**：Tailwind CSS（用于快速构建视觉层次）。
- **存储依赖**：浏览器原生 `localStorage` API。

## 10. 风险与注意事项

- **数据丢失风险**：由于数据存储在浏览器缓存中，用户清理缓存会导致数据清空。**（建议：在界面显著位置提示用户定期备份或说明存储机制）**
- **性能限制**：当任务数量超过 1000 条时，纯前端处理和 `localStorage` 读取可能出现微小延迟。
- **时间一致性**：延期判定依赖客户端系统时间，若用户系统时间不准，标记可能出现偏差。
