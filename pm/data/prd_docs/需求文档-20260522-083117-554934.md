# PRD 文档（个人作品集展示版）

> **说明**：本档为针对“3D卡通竞速赛车游戏”的正式需求文档，旨在作为个人作品集展示的核心功能定义。

## 1. 文档信息

- **项目名称**：3D 卡通竞速赛车游戏
- **需求名称**：个人作品集展示版功能开发

## 2. 需求背景

### 2.1 背景说明
本项目旨在开发一款具有高视觉表现力和成熟操作手感的 3D 赛车游戏，用于个人作品集展示。当前市场上爽快竞速类游戏（如《马里奥赛车》）深受喜爱，通过复刻并优化其核心机制（漂移、道具、AI 橡皮筋），可以充分展示开发者在 3D 渲染、物理引擎应用及复杂逻辑控制方面的技术实力。

### 2.2 需求目标
- **视觉表现**：实现精美的卡通渲染风格和动态音效。
- **核心手感**：打造具备“漂移喷气”机制的爽快操作体验。
- **系统完整性**：提供从菜单、角色选择到比赛结算的完整游戏闭环。
- **竞技性**：通过 AI 橡皮筋机制和随机道具系统确保比赛的趣味性和挑战性。

## 3. 需求范围

### 3.1 本次范围
- **核心玩法**：支持 5 个属性差异化角色、3 条复杂 3D 赛道（含坡道、跳跃点）。
- **对战模式**：本地同机双人左右分屏对战，支持 AI 赛车手加入。
- **关键机制**：漂移喷气系统（Mini-Turbo）、随机道具系统（盲盒机制）、赛道救援系统。
- **系统流程**：主菜单、角色/赛道选择、比赛 HUD、赛后结算。
- **技术实现**：基于 Web 3D 方案，支持动态音效（引擎声、3D 空间音效）。

### 3.2 非本次范围
- **网络功能**：不涉及在线联机对战。
- **持久化数据**：不涉及历史最快圈速或最高分记录的本地/云端保存。
- **进阶模式**：不涉及大奖赛（多场积分累计）模式。

## 4. 用户与使用场景

### 4.1 目标用户
- **招聘官/技术面试官**：通过演示评估开发者的技术深度。
- **本地双人玩家**：在同一台电脑上进行休闲对战的用户。

### 4.2 核心使用场景
1. **作品演示**：开发者启动游戏，展示卡通渲染效果，演示漂移喷气和道具交互。
2. **双人竞技**：两名玩家通过键盘（P1: WASD，P2: 方向键）在分屏下进行 3 圈环形赛道竞速。

## 5. 功能需求

### 5.1 功能概述
游戏提供完整的单场比赛流程。玩家选择角色和赛道后进入分屏比赛，通过漂移积攒加速、撞击盲盒获取道具互相攻击，并在 AI 橡皮筋机制的调节下，与电脑及另一名玩家竞争，率先完成 3 圈者获胜。

### 5.2 功能点明细

#### 功能点 1：漂移喷气系统 (Mini-Turbo)
- **功能描述**：玩家通过长时间漂移获得释放后的瞬间加速。
- **触发方式**：转弯时按下漂移键并维持。
- **处理逻辑**：
    1. 监测漂移持续时间。
    2. 视觉反馈：车轮火花颜色随时间由蓝变红（代表蓄力等级）。
    3. 释放逻辑：松开漂移键时，根据蓄力等级给予赛车瞬时速度增量。
- **输入项**：转向指令、漂移功能键。
- **输出结果**：火花特效、速度爆发。
- **异常情况**：漂移中撞击墙壁或障碍物，蓄力进度清零。

#### 功能点 2：随机道具系统
- **功能描述**：撞击赛道盲盒随机获得道具。
- **触发方式**：赛车碰撞赛道上的道具盲盒模型。
- **处理逻辑**：
    1. **概率计算**：基于玩家当前排名动态调整（落后者更高概率获得加速/护盾，领先者更高概率获得放置类道具）。
    2. **道具类型**：
        - 追踪型：导弹（自动锁定前方对手）。
        - 放置型：地雷/香蕉皮（原地放置）。
        - 自身强化型：无敌护盾/瞬间加速。
- **输入项**：碰撞事件、实时排名。
- **输出结果**：HUD 显示道具图标、触发后的道具效果。

#### 功能点 3：AI 橡皮筋机制 (Rubber Banding)
- **功能描述**：动态调整 AI 强度以维持比赛悬念。
- **处理逻辑**：
    - 当玩家领先较多时，AI 获得速度补偿（最高时速提升）。
    - 当玩家落后较多时，AI 适当减速等待。
- **输入项**：玩家与 AI 的实时距离、排名。
- **输出结果**：AI 赛车物理参数的实时微调。

#### 功能点 4：赛道救援系统
- **功能描述**：处理赛车掉出赛道边界的情况。
- **触发方式**：赛车坐标进入预设的“坠落区域”或离开赛道逻辑边界。
- **处理逻辑**：由“救援队”动画将赛车放回上一个经过的检查点（Checkpoint），并扣除少量时间或当前持有道具作为惩罚。

## 6. 业务规则

- **胜负规则**：环形赛道率先完成 3 圈的玩家/AI 判定为第一名，比赛进入结算。
- **操作分配**：
    - **玩家 1**：W/A/S/D 移动，空格键触发道具。
    - **玩家 2**：方向键移动，回车键触发道具。
- **地形物理规则**：
    - 草地/沙地：摩擦力增加，最高时速强制降低。
    - 冰面：侧滑力增加，转向灵敏度降低。
- **分屏规则**：屏幕强制执行**左右垂直平分**。

# 7. 页面 / 交互说明

### 7.1 页面说明
- **启动主菜单**：包含“开始游戏”、“退出”按钮。
- **选择界面**：
    - 角色选择：展示 5 个角色的属性（速度、加速度、转向、重量）。
    - 赛道选择：展示 3 条赛道的预览图及难度星级。
- **比赛界面 (HUD)**：
    - 左右分屏视野。
    - 元素：小地图（显示所有选手位置）、当前道具槽、圈数进度 (X/3)、实时排名、时速表。
- **结算界面**：显示最终排名榜单（1st - Nth）及“返回主菜单”按钮。

### 7.2 交互流程
1. 用户进入主菜单 -> 点击开始。
2. 玩家 1 与 玩家 2 依次确认角色 -> 共同确认赛道。
3. 加载 3D 场景 -> 倒计时 3-2-1-Go。
4. 比赛中：漂移、吃道具、躲避障碍、跳跃平台。
5. 终点结算 -> 展示排名 -> 点击返回。

## 8. 文案说明

- **操作提示**：P1: WASD + Space | P2: Arrows + Enter。
- **比赛状态**：Final Lap! (进入最后一圈提示)。
- **结算文案**：Winner is Player X! / You Finished Nth!。
- **异常提示**：Out of Bounds! (掉出赛道时)。

## 9. 数据与依赖

- **技术栈**：C# 后端（逻辑/配置管理）+ 静态页面前端（Web 3D 渲染引擎，如 Three.js 或 Unity WebGL）。
- **音效依赖**：
    - 引擎声：需支持根据速度/转速动态改变音调（Pitch）。
    - 空间音效：道具爆炸需具备 3D 空间衰减效果。
    - 音乐切换：进入最后一圈时，BPM 提升的背景音乐切换。

## 10. 风险与注意事项

- **性能风险**：Web 3D 分屏渲染相当于双倍渲染开销，需严格控制模型面数和特效粒子数量。
- **硬件限制**：部分廉价键盘存在“按键冲突（Ghosting）”，双人同时按下多个键位（如 WASD + 方向键 + 功能键）可能导致部分输入失效。
- **物理稳定性**：复杂 3D 赛道的跳跃平台需反复调试物理参数，避免赛车卡入模型缝隙。

## 11. 验收标准

- [ ] 游戏能正常加载并稳定维持分屏渲染帧率。
- [ ] P1 和 P2 能通过指定按键独立控制，互不干扰。
- [ ] 漂移蓄力火花颜色切换正常，松开后有明显的加速反馈。
- [ ] 道具盲盒能根据排名概率正确分发道具，且道具功能（导弹追踪、地雷放置等）正常。
- [ ] AI 赛车能自动寻路完成比赛，且表现出明显的“橡皮筋”速度补偿行为。
- [ ] 赛车掉落后能准确复位至最近检查点。
- [ ] 完成 3 圈后准确跳转结算页并显示正确排名。
