## 1. 范围与目标

- **项目名称**: D.CHQ.QDM Finished Lot 良率看板
- **需求名称**: Finished Lot 绩效趋势与缺陷损失占比看板
- **背景说明**: 该看板用于为工厂内不同产品提供当前关键良率指标的高层视图，并通过自动化脚本按计划每日更新，减少手工报表准备。
- **目标**: 通过展示整体良率趋势、分段/产品下钻、缺陷代码 Pareto、损失工序和根因责任归属，帮助良率曲线更快改善、快速降低生产成本、在不增加额外成本的情况下提升产出，并更早回收投资成本。

### 1.1 本次范围
- **Finished Lot Performance Overview Trend 页面**：展示 Finished Yield、最新周 Output、Yield、NSQM Loss。
- **Loss Ratio By Defect Code 页面**：展示 Top 10 到 Top 20 缺陷损失占比、缺陷代码趋势和原因部门分布。
- **统一筛选条件**：Customer、Plant、Date Type、Lot Type、Unit Type、Project Type。
- **计算逻辑**：Finished Yield 的批次级与周汇总计算逻辑实现。
- **数据集成**：对接 DS-01 与 DS-02 数据源。

## 1.2 非本次范围
- 自动优化工艺参数。
- 替代 QMS 正式缺陷判定流程。
- 供应商或客户投诉管理。

## 3. 系统用例

### 3.1 用例 01：查看良率趋势与明细
- **参与者**：Yield team 工程师/经理
- **触发条件**：用户访问 Overview 页面
- **前置条件**：用户已获得系统访问权限，后台数据已完成每日同步
- **主流程**：
    1. 系统加载默认筛选条件（Weekly, HVM, NSQM, Overall）。
    2. 系统从 SQLite 数据库查询汇总数据。
    3. 页面渲染 Finished Yield 趋势折线图。
    4. 页面右侧渲染最新周的 Output、Yield、NSQM Loss 卡片。
- **后置条件**：用户看到当前生产状态的高层视图。
- **验收检查点**：图表数值与 QDM 源表一致，响应时间 < 3s。

### 3.2 用例 02：多维筛选联动
- **参与者**：QDM 用户
- **触发条件**：用户修改筛选栏中的任一条件（如切换 Plant）
- **主流程**：
    1. 用户在下拉框选择新的筛选值。
    2. 前端触发 API 请求，携带所有当前筛选上下文。
    3. 后端执行过滤查询并返回更新后的 JSON 数据。
    4. 页面所有图表（趋势图、Pareto 图、明细表）同步刷新，无需整页重载。
- **异常流程**：若筛选组合下无数据，图表应显示“No Data Found”占位符而非空白或报错。
- **验收检查点**：所有受影响图表必须同步更新，筛选上下文在导出时需保留。

## 4. 功能需求

### 4.1 核心分析页面
- **Finished Lot Performance Overview Trend**: 
    - 主图：展示随时间变化的 Finished Yield。
    - 交互：点击趋势点，右侧明细视图切换至该时间段。
- **Loss Ratio By Defect Code**:
    - 主图：Top 10-20 缺陷代码 Pareto 柱状图。
    - 辅助图：选中缺陷的趋势图及责任部门分布饼图。

### 4.2 业务规则
- **良率计算**: $Finished Yield = \prod (Output_i / Input_i)$，即各关键工序良率的连续乘积。
- **默认值**: Customer=All, Plant=All, Date Type=Weekly, Lot Type=HVM, Unit Type=NSQM, Project Type=Overall。
- **导出规则**: 导出数据必须包含当前生效的筛选条件作为页眉或元数据。

## 5. 非功能需求

- **性能**: 页面首屏加载及筛选响应目标为 3 秒内。
- **兼容性**: 必须在企业基线浏览器（Chrome, Edge）上完美运行。
- **响应式**: 支持桌面端（主要）和平板电脑（次要）布局，无组件重叠。
- **可用性**: 交互式图例需支持键盘访问，Tooltip 需在触屏上通过点击触发。

---

## 6. 高层架构设计

系统采用典型的三层架构：
- **表现层 (Frontend)**: HTML5, CSS (Bootstrap), 原生 JavaScript (或 jQuery) 进行 DOM 操作与图表渲染（建议使用 Chart.js 或 ECharts）。
- **业务逻辑层 (Backend)**: C# (ASP.NET Core Web API)，负责数据过滤、良率逻辑计算及 API 路由。
- **数据层 (Database)**: SQLite，存储从 QDM 生产库同步过来的汇总数据，以保证看板的查询性能。

---

## 7. 模块职责划分

- **Web UI 模块**: 负责筛选栏渲染、图表组件初始化、响应式布局管理。
- **API 服务模块**: 接收前端请求，解析筛选参数，调用数据访问层。
- **计算引擎模块**: 实现批次级与周汇总良率的特定数学公式。

| 接口名称 | 路径 | 方法 | 说明 |
| :--- | :--- | :--- | :--- |
| 获取筛选元数据 | `/api/metadata/filters` | GET | 返回下拉框可选值 |

## 9. 数据模型与数据库设计

### 9.1 候选表设计

#### 表 1: `FinishedLotSummary` (对应 DS-01)
用于存储良率趋势和产出汇总。
- **PK**: `SummaryId` (INTEGER)
- **字段**: 
    - `ATSDate` (TEXT/DATETIME) - 索引建议
    - `DateType` (TEXT) - Weekly/Monthly/Quarterly
    - `Customer`, `Plant`, `LotType`, `UnitType`, `ProjectType` (TEXT) - 复合索引建议
    - `Yield` (REAL)
    - `Output_NSQM` (INTEGER)
    - `Input_Qty` (INTEGER)

#### 表 2: `DefectSummary` (对应 DS-02)
用于存储缺陷损失占比。
- **PK**: `DefectId` (INTEGER)
- **FK**: `SummaryId` (关联至 FinishedLotSummary)
- **字段**:
    - `DefectCode` (TEXT) - 唯一约束/索引
    - `DefectQty` (INTEGER)
    - `LossRatio` (REAL)
    - `Department` (TEXT)

### 9.2 数据约束与一致性
- **基数**: `FinishedLotSummary` 与 `DefectSummary` 为 1:N 关系。
- **审计**: 每行包含 `LastUpdated` 时间戳。
- **敏感数据**: 无个人隐私数据，但 Yield 数据属于商业机密，需在 API 层进行角色权限校验。

## 10. 关键流程 / 时序说明

1. **初始化**: 前端请求 `/filters` -> 后端查询 SQLite 唯一值 -> 返回下拉列表。
2. **数据加载**: 前端发送默认参数至 `/trend` -> 后端执行 SQL 聚合 -> 返回 JSON -> 前端渲染图表。
3. **下钻分析**: 用户点击折线图点 -> 前端捕获 `ATSDate` -> 发送请求至 `/defect/analysis` -> 更新 Pareto 图。

## 14. 测试与验收方案

- **单元测试**: 验证良率计算公式在各种 Input/Output 组合下的准确性。
- **集成测试**: 验证筛选器改变后，所有图表的数据一致性。

---

## 15. 风险、权衡与假设

- **风险**: 若 SQLite 并发写入过高可能导致锁定（由于是看板系统，读多写少，风险较低）。
- **权衡**: 放弃了复杂的 BI 建模，选择轻量级 SQLite 以换取极速的响应性能。
- **假设**: 假设源系统 DS-01/02 能够按时提供清洗后的汇总数据。
