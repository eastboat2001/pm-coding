## 2. 背景与目标

### 2.1 背景
仓库管理员目前需要每日例行检查库存情况以决定补货计划。现有的手工对账方式效率低且容易遗漏风险。业务需要一个自动化的可视化工具，通过动态销量数据识别缺货风险，并提供量化的补货建议。

### 2.2 目标
- **宏观监控**：通过饼图直观展示各仓库/品类的库存风险分布（严重缺货、一般预警、库存充足）。
- **决策辅助**：基于“剩余可售天数”动态计算补货量，辅助管理员快速做出补货决策。
- **灵活配置**：支持按仓库、分类或 SKU 维度自定义预警阈值。

### 2.3 成功标准
- 预警状态分类逻辑准确，符合业务定义的阈值规则。
- 建议补货量计算准确，已扣除在途库存。
- 页面数据每 4 小时自动更新，无需人工干预。

## 5. 数据说明

### 5.1 数据来源

| 来源 / 表 / API | 负责人 | 刷新频率 | 数据粒度 | 备注 |
| --- | --- | --- | --- | --- |
| 库存表 (Excel) | 外部部门 | 每 4 小时 | SKU + 仓库 | 存放当前实物库存 |
| 销量表 (Excel) | 外部部门 | 每 4 小时 | SKU + 仓库 | 存放过去 7 天销量明细 |
| 在途表 (Excel) | 外部部门 | 每 4 小时 | SKU + 仓库 | 存放已下单未入库数量 |

### 5.2 关键字段与业务定义

| 字段名 | 业务定义 | 数据类型 | 是否必填 | 来源映射 / 逻辑 |
| --- | --- | --- | --- | --- |
| SKU 编码 | 商品唯一标识 | 文本 | Y | 统一关联键 |
| 仓库 ID | 仓库唯一标识 | 文本 | Y | 统一关联键 |
| 当前库存 | 仓库实物库存量 | 数字 | Y | 库存表 |
| 在途库存 | 已下单未入库量 | 数字 | Y | 在途表 |
| 7天日均销量 | 过去7天销量总和 / 7 | 数字 | Y | 销量表计算 |
| 预警阈值 (X) | 触发预警的天数基准 | 数字 | Y | 阈值配置页 (SKU级 > 分类级) |

### 5.3 计算与逻辑规则

1.  **剩余可售天数 (RDS)** = `当前库存 / 7天日均销量`
    *   *特殊处理*：若 7 天日均销量为 0，RDS 视为无穷大，状态归为“库存充足”。
2.  **预警状态判定**：
    *   **严重缺货**：`RDS < (X * 50%)` 或 `RDS < 2天`。
    *   **一般预警**：`RDS < X` 且不满足严重缺货条件。
    *   **库存充足**：`RDS >= X`。
3.  **建议补货量** = `(7天日均销量 * 14) - (当前库存 + 在途库存)`
    *   *特殊处理*：若计算结果 < 0，则显示为 0。
4.  **数据缺失处理**：若 SKU 缺少库存或销量关键数据，则跳过该 SKU 不做展示。

## 6. 页面与图表呈现

### 6.1 页面布局
- **顶部**：仓库筛选（单选/多选）、商品分类筛选（多选）。
- **中部**：预警状态分布饼图（展示严重缺货、一般预警、库存充足的品种数占比）。
- **底部**：SKU 明细表（点击饼图切片可联动过滤）。

### 6.2 图表规格

| 字段 | 内容 |
| --- | --- |
| 图表类型 | 饼图 |
| 核心指标 | 品种数占比 |
| 维度 | 预警状态 (严重缺货 / 一般预警 / 库存充足) |
| 排序 | 按状态严重程度排序 |
| 悬浮提示内容 | 状态名称、品种数量、百分比 |
| 下钻行为 | 点击切片，下方明细表仅显示该状态下的 SKU |

### 6.3 查询条件与筛选

| 筛选字段 | 控件类型 | 默认值 | 是否必填 | 备注 |

| 列名 | 来源字段 | 展示格式 | 是否可排序 | 备注 |

## 8. 开发要求

## 8.1 技术规格
- **数据集成**：需开发定时任务，每 4 小时扫描共享文件夹，解析 Excel 并更新数据库。
- **阈值配置**：需提供独立页面，支持“仓库+分类”和“仓库+SKU”两个层级的配置，遵循 **SKU 优先** 原则。

### 8.2 性能与安全
- **性能**：Excel 解析及看板加载应在 5 秒内完成。
- **错误处理**：若 Excel 文件缺失或格式错误，需在后台记录日志，前端看板显示“数据更新异常”提醒。
