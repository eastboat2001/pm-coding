# PRD 文档（草案）

> **文档说明**：本 PRD 基于收集到的个人记账系统需求整理而成。当前需求收集进度为 100%，部分交互细节基于 PC 端使用习惯进行了合理假设（已标注）。

## 1. 文档信息

- **项目名称**：个人记账系统 (Demo 版)
- **需求名称**：个人日常消费记账系统需求规格说明书

## 2. 需求背景

### 2.1 背景说明

用户需要一个轻量、私有的本地记账工具，用于追踪日常的个人收入与支出情况。目前市面上的记账软件大多包含社交、理财广告或强制云同步，用户希望拥有一个纯净、手动录入且数据存储在本地的解决方案。

### 2.2 需求目标

- 实现手动记录每一笔收支明细。
- 支持自定义收支分类和支付方式标签。
- 提供按月份和分类筛选的功能，并实时汇总收支结余。
- 保证本地私有化运行，不依赖外部账号系统。

## 3. 需求范围

### 3.1 本次范围

- **收支记录管理**：支持账目的增、删、改、查（CRUD）。
- **配置项管理**：自定义管理“消费分类”（区分收入/支出）和“支付方式”。
- **筛选与统计**：支持按“月份”和“分类”筛选，实时汇总总收入、总支出和结余。
- **数据存储**：使用本地 SQLite 数据库存储文本和数字信息。
- **终端适配**：适配电脑（PC）浏览器。

### 3.2 非本次范围

- 不涉及用户登录与权限管理（单用户本地模式）。
- 不涉及账户余额自动对账（支付方式仅作为标签）。
- 不涉及复杂统计图表（如饼图、折线图）。
- 不涉及数据导出（Excel/CSV）或第三方账单导入。
- 不涉及图片、附件上传或多币种支持。

## 4. 用户与使用场景

### 4.1 目标用户

- 追求财务隐私、习惯手动记账的个人用户。

### 4.2 核心使用场景

1. **每日记账**：用户在电脑前开启系统，录入当天的消费或收入，选择对应的分类和支付方式。
2. **月度回顾**：用户通过月份筛选器查看本月所有账目，并查看顶部的总支出和结余。
3. **分类调整**：用户根据消费习惯的变化，新增或修改消费分类名称。

## 5. 功能需求

### 5.1 功能概述

系统提供纯手动的收支记录管理功能，支持基于“收支类型”隔离的分类选择，并能根据筛选条件实时计算汇总数据。

### 5.2 功能点明细

#### 功能点 1：收支记录录入与管理

- **功能描述**：用户记录每一笔账务明细，并可对历史记录进行编辑或删除。
- **触发方式**：点击“新增账目”按钮或点击已有记录的“编辑/删除”图标。
- **处理逻辑**：
    - 账目类型（收入/支出）为必填。
    - 金额支持两位小数，必填。
    - 日期精确到天，默认填充为“当天”。
    - 分类与支付方式为选填。
    - 录入收入时，分类下拉框仅显示“收入类”分类；支出同理。
- **输入项**：类型、金额、日期、分类、支付方式、备注。
- **输出结果**：历史记录列表更新，统计汇总值更新。
- **异常情况**：未填写必填项（类型、金额、日期）时，系统提示并拦截提交。

#### 功能点 2：配置项管理（分类与支付方式）

- **功能描述**：用户自定义账目的维度标签。
- **触发方式**：进入配置管理页面。
- **处理逻辑**：
    - 支持新增、修改分类名称及所属类型（收入/支出）。
    - 支持新增、修改支付方式名称。
    - **引用保护**：若某个分类或支付方式已被账目记录引用，则不允许删除。
- **输入项**：名称、所属类型（仅限分类）。
- **输出结果**：配置列表更新。
- **异常情况**：删除已被引用的配置项时，系统弹出警告提示。

#### 功能点 3：筛选与汇总统计

- **功能描述**：根据用户选择的时间和分类范围，展示明细并计算总额。
- **触发方式**：切换月份下拉框或分类下拉框。
- **处理逻辑**：
    - 默认进入系统时展示“全部”历史记录。
    - 汇总公式：`总收入 = 筛选范围内所有收入之和`；`总支出 = 筛选范围内所有支出之和`；`结余 = 总收入 - 总支出`。
    - 汇总金额随筛选条件实时联动。
- **输入项**：月份（年-月）、分类。
- **输出结果**：过滤后的账目列表、实时汇总数值。

## 6. 业务规则

- **收支分类隔离**：录入界面必须先选“类型”，再根据类型过滤“分类”选项。
- **排序规则**：历史列表统一按“日期”字段倒序排列（最近的日期在前）。
- **数据精度**：金额字段强制保留两位小数。
- **引用保护规则**：已使用的配置项（分类/支付方式）禁止删除，以保证历史数据完整性。

## 7. 页面 / 交互说明

### 7.1 页面说明

- **主列表页**：
    - **入口位置**：系统首页。
    - **页面元素**：月份筛选器、分类筛选器、汇总统计栏（总收/总支/结余）、历史记录长列表（支持滚动）、新增按钮。
    - **按钮操作**：点击新增打开弹窗；点击记录行操作按钮进行编辑或删除。
- **配置管理页**：
    - **入口位置**：侧边栏或顶部导航（**假设**：系统采用简单的侧边导航结构）。
    - **页面元素**：分类管理表格（区分收支类型）、支付方式管理表格。

## 7.2 交互流程

1. 用户点击“新增” -> 弹出对话框。
2. 用户选择“支出” -> 分类下拉框自动加载“餐饮、交通”等支出类选项。
3. 用户填写金额并提交 -> 对话框关闭，列表首行出现新记录，顶部汇总数值更新。
4. 用户在筛选器选择“2023-10” -> 列表仅显示10月账目，汇总栏显示10月统计。

## 8. 文案说明

- **统计标签**：总收入、总支出、结余。
- **操作提示**：确认删除该笔记录吗？
- **错误提示**：该分类已被使用，无法删除。
- **默认状态**：暂无数据。

## 9. 数据与依赖

- **技术栈**：前端 Vue，后端 Flask，数据库 SQLite。
- **部署环境**：本地运行，依赖本地 Python 环境及浏览器。
- **数据依赖**：账目记录强依赖于分类表和支付方式表的 ID 关联。

## 10. 风险与注意事项

- **数据备份**：由于是本地 SQLite 存储，建议用户定期手动备份数据库文件，防止系统重装或硬盘损坏导致数据丢失。
- **并发限制**：系统设计为单人使用，不支持多端同时写入。

## 11. 验收标准

- [ ] 能够成功记录一笔收支，且金额支持两位小数。
- [ ] 在历史列表中，账目按日期从近到远排列。
- [ ] 切换月份或分类筛选后，顶部的总收入、总支出和结余计算准确。
- [ ] 尝试删除一个已有账目关联的分类时，系统应报错拦截。
- [ ] 编辑或删除账目后，列表数据和汇总统计应立即同步更新。
