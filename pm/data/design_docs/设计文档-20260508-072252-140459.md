## 1. 范围与目标

- **项目名称**: 日历网页 (Calendar Web App)
- **需求名称**: 日历网页基础需求定义
- **背景说明**: 用户希望开发一个个人使用的日历网页，用于日常日期查看及相关事务记录。
- **目标**: 交付一个轻量级、响应式的 Web 日历应用，支持基础的日期浏览与日程持久化存储。

### 1.1 本次范围
- **前端展示**: 基于 Vue 的日历网格视图（月视图）。
- **后端服务**: 基于 Flask 的 RESTful API，处理业务逻辑。
- **数据存储**: 使用 SQLite 存储用户生成的日程数据。
- **基础交互**: 日程的创建、查看、编辑与删除 (CRUD)。

### 1.2 非本次范围
- 多用户注册与登录系统 (TBD)
- 外部日历（如 Google Calendar）同步
- 复杂的重复日程逻辑（如：每隔两周的周三）
- 实时推送提醒（Web Push）

## 2. 用户角色与参与方
- **个人用户**: 系统的唯一使用者，负责管理自己的日程信息。

## 3. 系统用例

### 用例 1：查看月度日程
- **参与者**: 个人用户
- **触发条件**: 用户访问网页根路径
- **前置条件**: 系统已部署并正常运行
- **主流程**:
    1. 用户打开浏览器访问应用。
    2. 前端向后端请求当前月份的日程数据。
    3. 后端从 SQLite 查询数据并返回 JSON。
    4. 前端渲染日历网格，并在对应日期显示日程标记。
- **验收检查点**: 日历显示正确（日期与星期对应），已有日程能准确显示在对应格子里。

### 用例 2：添加新日程
- **参与者**: 个人用户
- **触发条件**: 用户点击日历中的某个日期格
- **前置条件**: 处于日历主页
- **主流程**:
    1. 用户点击特定日期。
    2. 系统弹出“新增日程”对话框。
    3. 用户输入标题、描述、时间。
    4. 用户点击“保存”。
    5. 前端调用 POST API，后端写入数据库。
- **备选/异常流程**: 如果标题为空，系统提示“标题不能为空”并阻止提交。
- **验收检查点**: 保存后页面不刷新即可看到新日程，数据库中新增一条记录。

## 4. 功能需求

### 4.1 功能概述
实现一个基于 Web 的日历应用，支持基础的日期查看及日程管理。

### 4.2 功能明细
- **日历视图**: 支持按月切换查看日期。
- **日程管理**: 
    - 点击日期创建日程。
    - 点击已有日程进行编辑或删除。
- **数据持久化**: 所有日程保存至本地数据库，刷新页面不丢失。

### 4.3 业务规则
- **日期范围**: 默认支持当前年份前后 10 年的查看。
- **冲突处理**: 同一时间段允许存在多个日程（不设硬性冲突校验）。

## 5. 非功能需求
- **易用性**: 界面简洁，操作直观，无需说明书。
- **性能**: 页面加载时间 < 2s，API 响应时间 < 500ms。
- **响应式**: 适配桌面端浏览器（移动端适配 TBD）。

# 6. 高层架构设计
采用经典的 **前后端分离单体架构**：
- **前端 (Frontend)**: Vue.js (SPA 模式)，负责 UI 渲染与交互逻辑。
- **后端 (Backend)**: Flask (Python)，负责提供 RESTful API 与数据库交互。
- **数据库 (Database)**: SQLite，以单文件形式存储在后端服务器目录。

## 7. 模块职责划分

### 7.1 候选模块
- **CalendarUI**: 负责日历逻辑计算（闰年、月份天数、星期对齐）。
- **EventService**: 负责日程的增删改查逻辑。
- **DBConnector**: 负责与 SQLite 的连接与 SQL 执行。

### 7.2 页面 / 触点说明
## 页面 1: 日历主页
- **页面名称**: 日历主页
- **入口位置**: `/`
- **页面元素**: 月份切换按钮、日历网格、日程详情弹窗。
- **按钮动作**: 
    - `Prev/Next`: 切换月份。
    - `Today`: 回到今天。
    - `Save`: 提交日程。

## 8. API 设计（草案）

| 接口路径 | 方法 | 说明 | 参数 (JSON) |
| :--- | :--- | :--- | :--- |
| `/api/events` | GET | 获取指定范围内的日程 | `?start=2023-10-01&end=2023-10-31` |
| `/api/events` | POST | 创建新日程 | `{title, description, start_time, end_time}` |
| `/api/events/<id>` | PUT | 更新日程 | `{title, description, start_time, end_time}` |
| `/api/events/<id>` | DELETE | 删除日程 | - |

## 9. 数据模型与数据库设计

### 9.1 数据库选型
- **SQLite**: 适合个人 Demo，无需独立安装数据库服务。

### 9.2 实体表设计
**表名: `events`** (存储日程信息)

| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY, AUTOINCREMENT | 唯一标识 |
| `title` | TEXT | NOT NULL | 日程标题 |
| `description` | TEXT | - | 详细描述 |
| `start_time` | DATETIME | NOT NULL | 开始时间 |
| `end_time` | DATETIME | NOT NULL | 结束时间 |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

- **索引建议**: 在 `start_time` 字段建立索引以加速范围查询。
- **数据约束**: `end_time` 必须大于等于 `start_time`。

## 10. 关键流程 / 时序说明
1. **初始化流程**: 用户打开页面 -> 前端计算当前月份 -> 调用 `GET /api/events` -> 后端查询 SQLite -> 返回数据 -> 前端渲染。
2. **更新流程**: 用户修改日程 -> 点击保存 -> 前端调用 `PUT /api/events/<id>` -> 后端更新数据库 -> 返回成功 -> 前端局部刷新视图。

## 11. 安全、隐私与合规
- **输入校验**: 后端必须对所有传入的 `title` 和 `description` 进行长度校验和转义，防止 XSS 和 SQL 注入。
- **数据安全**: 由于是个人项目，暂不考虑多租户隔离。

## 12. 可观测性与运维
- **日志**: Flask 开启基础的 `logging`，记录 API 请求错误。
- **监控**: 暂无。

 13. 部署与环境规划
- **开发环境**: 
    - 前端: Node.js + Vite/Vue CLI
    - 后端: Python 3.x + Flask
- **生产环境 (Demo)**:

    - 前端打包为静态文件，由 Flask 或 Nginx 托管。

## 14. 测试与验收方案
- **冒烟测试**: 确保能正常打开页面并看到当前日期。
- **功能测试**: 依次执行 CRUD 操作，确认数据在刷新后依然存在。

## 15. 风险、权衡与假设
- **假设**: 假设用户接受 Vue + Flask + SQLite 的技术栈。
- **权衡**: 为了快速落地，暂不引入 Redis 缓存和复杂的权限控制。
- **风险**: SQLite 不支持高并发写入（但在个人 Demo 场景下不是问题）。
