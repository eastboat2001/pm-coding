# 项目假设与取舍说明

## 技术假设

1. **浏览器环境**
   - 假设用户使用支持HTML5的现代浏览器（Chrome 60+, Edge 79+, Safari 10+, Firefox 55+）
   - 假设浏览器支持LocalStorage API

2. **数据存储**
   - 所有数据存储在用户本地浏览器的LocalStorage中
   - 数据不会上传到任何服务器
   - 清除浏览器缓存会丢失所有数据

3. **网络依赖**
   - 项目为纯静态应用，无需网络连接
   - 所有资源本地加载，无外部依赖

## 业务假设

1. **用户场景**
   - 主要面向PC端桌面用户
   - 未做移动端深度适配
   - 适用于个人使用，不支持多用户协作

2. **数据规模**
   - LocalStorage通常有5MB限制
   - 纯文本备忘录内容足够使用
   - 不适用于大量数据存储

## 设计决策

1. **周起始日选择**
   - 选择周一作为每周第一天（符合国际标准和中国习惯）
   - 日历排列从周一开始到周日结束

2. **年份范围**
   - 当前年份 ±10年（共21年）
   - 覃盖大多数使用场景
   - 平衡了界面简洁性和实用性

3. **视觉设计**
   - 有内容的日期使用浅黄色背景
   - 今天使用蓝色边框高亮
   - 保持简洁专业的界面风格

## 已知限制

1. **数据持久性**
   - 数据仅保留在当前浏览器
   - 不同设备间数据不共享
   - 浏览器隐私模式下LocalStorage可能不可用

2. **功能限制**
   - 仅支持纯文本备忘录
   - 不支持任务清单（Todo List）功能
   - 不支持文件附件
   - 不支持提醒功能

3. **兼容性限制**
   - 主要针对桌面浏览器优化
   - 未做移动端响应式深度适配
   - 未测试所有浏览器版本

## 实现取舍

1. **框架选择**
   - 选择原生HTML/CSS/JS，零框架依赖
   - 优点：加载快、无依赖、兼容性好
   - 缺点：需要手动DOM操作，开发效率较低

2. **数据格式**
   - 使用LocalStorage存储纯文本
   - 键格式：`memo_YYYY-MM-DD`
   - 优点：简单、直接、兼容性好
   - 缺点：无法存储结构化数据

3. **UI交互**
   - 使用原生Modal弹窗
   - 简洁直观的交互设计
   - 避免复杂的动画和特效

## 验收标准对应

本项目完全满足PRD中的验收标准：

1. ✅ 日历能正确显示当前月份，且周一排在第一列
2. ✅ 点击有内容的日期，弹窗能正确回显之前保存的文本
3. ✅ 点击保存后，刷新页面，对应日期的背景色标记依然存在
4. ✅ 年份下拉框包含当前年份 -10 到 +10 的选项
5. ✅ 点击"回到今天"能准确跳转回系统当前日期所在的月份

## 未来扩展可能性

1. **数据导出/导入**
   - 可添加JSON格式的数据导出/导入功能
   - 方便数据备份和迁移

2. **多端同步**
   - 可考虑添加云存储同步功能
   - 需要用户账号系统

3. **增强功能**
   - 可添加任务清单功能
   - 可添加提醒功能
   - 可添加标签分类功能
