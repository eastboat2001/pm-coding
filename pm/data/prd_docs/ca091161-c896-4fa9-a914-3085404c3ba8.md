# PRD 文档（草案）- 个人记账本

> **注意：** 本文档基于初步需求收集生成，部分功能点（如修改/删除操作）尚未最终确认。文档中包含基于常识的合理假设，请在评审时重点关注。

## 1. 文档信息

- **项目名称**：个人记账本
- **需求名称**：基础收支记录与统计系统

## 2. 需求背景

### 2.1 背景说明

用户需要一个极简的个人财务管理工具，用于记录日常的每一笔收入和支出。当前市面上的记账软件往往过于复杂（涉及银行卡同步、理财产品等），用户希望有一个专注于“记录流水”和“查看统计”的本地化工具。

### 2.2 需求目标

- 提供快速的收支记录能力。
- 支持用户根据个人习惯自定义收支分类。
- 自动生成日度和月度的收支汇总，帮助用户了解财务状况。

## 3. 需求范围

### 3.1 本次范围

- **收支记录**：支持金额、类型（收/支）、分类、备注的记录。
- **分类管理**：支持用户自定义分类名称。
- **自动统计**：系统自动计算每日和每月的总收入与总支出。
- **本地存储**：数据仅保存在用户设备本地。

### 3.2 非本次范围

- **多账户管理**：不涉及现金、银行卡、支付宝等具体账户的余额追踪。
- **用户体系**：不涉及登录、注册及云端数据同步。
- **历史补记**：不支持修改账单日期，仅限记录当天账单。

## 4. 用户与使用场景

### 4.1 目标用户

希望简单记录日常流水、不需要复杂账务管理的个人用户。

### 4.2 核心使用场景

1. **即时记账**：用户在产生消费（如买咖啡）后，打开应用，输入金额并选择“餐饮”分类，添加备注后保存。
2. **财务复盘**：用户在晚间或月底打开应用，查看系统自动汇总的今日总支出或本月总盈亏。
3. **分类个性化**：用户根据需求，将预设的“交通”分类修改为更具体的“打车”。

## 5. 功能需求

## 5.1 功能概述

系统核心为基于本地存储的收支流水记录，通过自动抓取系统时间确保记录的实时性，并提供多维度的自动汇总统计。

### 5.2 功能点明细

# 功能点 1：收支流水记录

- **功能描述**：用户记录每一笔收入或支出信息。
- **触发方式**：用户在记账页面点击“保存”按钮。
- **处理逻辑**：系统自动获取当前系统日期（不可修改），结合用户输入的金额、分类和备注进行保存。
- **输入项**：金额（必填）、收支类型（收入/支出）、分类（必选）、备注（可选）。
- **输出结果**：保存成功并跳转至流水列表，列表更新。
- **异常情况**：金额为空或输入非数字字符时，提示“请输入有效的金额”。

#### 功能点 2：自定义分类管理

- **功能描述**：用户管理收支的分类标签。
- **触发方式**：用户进入分类设置页面。
- **处理逻辑**：允许用户新增分类或修改现有分类名称。
- **输入项**：分类名称。
- **输出结果**：记账时的分类下拉列表同步更新。
- **异常情况**：分类名称重复时，提示“该分类已存在”。

#### 功能点 3：自动统计汇总

- **功能描述**：系统根据日期自动计算汇总数据。
- **触发方式**：用户进入首页或统计页面。
- **处理逻辑**：系统遍历本地记录，按当前日期和当前月份分别累加收入和支出金额。
- **输入项**：本地历史账单数据。
- **输出结果**：展示“今日总收入/支出”及“本月总收入/支出”。
- **异常情况**：无数据时显示为 0.00。

## 6. 业务规则

1. **日期锁定规则**：账单日期强制为记录时的当前日期，不支持用户手动选择或修改日期。
2. **无余额校验规则**：系统不维护账户余额，仅展示流水统计，因此允许支出大于收入（即统计结果可为负数）。
3. **分类关联规则**：若修改了分类名称，历史已记录在该分类下的账单名称应同步更新（**假设**）。

## 7. 页面 / 交互说明

### 7.1 页面说明

- **首页（流水列表）**：
    - 入口位置：应用启动首屏。
    - 页面元素：今日/本月统计汇总、按时间倒序的流水列表、新增记账入口。
- **记账页**：
    - 入口位置：首页点击“+”或“新增”按钮。
    - 页面元素：数字键盘、收入/支出切换开关、分类选择器、备注输入框。
- **分类管理页**：
    - 入口位置：设置或记账页分类选择末尾。
    - 页面元素：分类列表、编辑按钮、新增分类按钮。

### 7.2 交互流程

1. 用户点击首页“新增”按钮进入记账页。
2. 输入金额，选择“支出”，选择“餐饮”分类。
3. 点击“保存”。
4. 系统关闭记账页，返回首页，首页顶部的“今日支出”实时增加。

## 8. 文案说明

- **按钮文案**：保存、新增分类、确认修改。
- **空状态提示**：今天还没有记账哦。
- **错误提示**：金额不能为空；分类名称已存在。

## 9. 数据与依赖

- **数据存储**：完全依赖设备本地存储（如 LocalStorage 或本地数据库），无需网络接口。
- **系统时间**：依赖设备系统时间用于生成账单日期。

## 10. 风险与注意事项

- **无法补记风险**：由于不支持修改日期，用户若当天忘记记账，后续无法回溯补记到准确日期。
- **数据丢失风险**：由于是纯本地存储，若用户清理应用缓存或卸载应用，数据将无法找回。
- **分类删除影响（假设）**：若未来增加删除分类功能，需考虑已关联该分类的账单如何显示。

## 11. 开放问题 (Open Questions)

1. **修改与删除**：是否需要支持对已保存的账单进行“修改金额/备注”或“删除”操作？（待确认）
2. **统计展示**：统计汇总仅需文字展示，还是需要柱状图/饼图等可视化图表？（待确认）
3. **预设分类**：系统是否需要内置一套初始分类（如餐饮、交通、购物、工资）？（建议增加）

## 12. 验收标准 (Acceptance Criteria)

1. 用户能够成功保存一笔包含金额、分类和备注的账单。
2. 账单列表中显示的日期必须是记录当天的日期，且用户无法更改。
3. 用户新增或修改的分类能够立即在记账时的分类选项中生效。
4. 首页显示的日统计和月统计数值必须与对应周期内的明细金额之和完全相等。
