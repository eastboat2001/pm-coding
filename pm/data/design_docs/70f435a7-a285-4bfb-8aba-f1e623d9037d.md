# 系统设计文档

> **文档说明**：本方案旨在为“库存补货决策辅助系统”提供技术落地指导。系统将基于 C# 后端、SQLite 数据库及原生前端技术栈构建，核心逻辑围绕 Excel 数据自动化集成与动态库存预警计算展开。

---

## 1. 范围与目标

- **项目名称**: 库存补货决策辅助系统
- **需求名称**: 低库存预警看板需求
- **背景说明**: 仓库管理员需要每日例行检查库存情况，以决定是否需要补货。目前需要一个可视化工具来识别风险并提供补货建议。
- **目标**: 通过动态计算“剩余可售天数”并对比预警阈值，辅助仓库管理员快速识别缺货风险并获取建议补货量，提高补货决策的效率和准确性。

## 1.1 本次范围
- 预警状态分布饼图（严重缺货、一般预警、库存充足）。
- 补货明细表（含建议补货量计算）。
- 仓库及商品分类筛选功能。
- 在线阈值配置页面（支持 SKU 和分类级，遵循 SKU 优先原则）。
- 自动读取共享文件夹 Excel 数据源（每 4 小时一次）。
- 基于仓库的数据权限隔离。

### 1.2 非本次范围
- 自动对接下游系统生成采购单。
- 阈值修改的历史审计日志记录。
- 销量预测算法（仅使用过去 7 天均值）。

## 3. 系统用例

### 3.1 用例：每日库存风险检查
- **参与者**: 仓库管理员（普通/配置）
- **触发条件**: 管理员登录系统
- **前置条件**: 系统已完成最近一次 Excel 数据同步
- **主流程**:
    1. 管理员在看板顶部选择所属“仓库”。
    2. 系统加载预警状态饼图，展示该仓库下各风险等级的品种占比。
    3. 管理员点击“严重缺货”饼图切片。
    4. 下方明细表联动展示所有严重缺货的 SKU、当前库存、在途库存及“建议补货量”。
- **验收检查点**: 饼图占比与明细表数量一致；建议补货量计算公式正确。

### 3.2 用例：预警阈值个性化调整
- **参与者**: 仓库管理员（配置）
- **触发条件**: 业务策略调整（如大促前夕）
- **主流程**:
    1. 进入“阈值配置页”。
    2. 选择特定仓库及 SKU（或分类）。
    3. 输入新的预警天数 $X$。
    4. 点击保存。
- **后置条件**: 看板在下一次刷新或计算时立即应用新阈值。
- **验收检查点**: SKU 级配置生效后，原有的分类级配置被覆盖。

## 4. 功能需求

### 4.1 功能明细
- **数据集成引擎**: 每 4 小时扫描共享文件夹，解析《库存表》、《销量表》、《在途表》。
- **预警计算引擎**: 
    - 剩余天数 = 当前库存 / (过去 7 天总销量 / 7)。
    - 建议补货量 = (日均销量 * 14) - (当前库存 + 在途库存)，结果 < 0 则取 0。
- **看板展示**: 饼图支持按状态（方案 A）划分；明细表支持按仓库/分类筛选。

---

## 5. 非功能需求

- **时效性**: 数据更新周期为 4 小时，页面需显示“数据最后更新时间”。
- **准确性**: 零销量 SKU 必须标记为“库存充足”，避免误报。
- **性能**: 即使 SKU 达到万级，看板加载时间应控制在 2 秒内（利用 SQLite 索引）。
- **容错性**: Excel 格式错误或关键字段缺失时，跳过该行记录并记录错误日志。

---

## 6. 高层架构设计

系统采用典型的三层架构，配合后台任务处理数据集成：
- **前端层**: 静态 HTML/CSS/原生 JavaScript，通过 Fetch API 与后端交互。
- **应用服务层 (C#)**: 
    - **Web API**: 提供看板数据、明细查询及阈值设置接口。
    - **Scheduled Task**: 定时任务（如使用 Quartz.NET 或内置 Timer）执行 Excel 解析。
- **数据层 (SQLite)**: 存储解析后的业务数据及用户配置。

---

## 7. 模块职责划分

- **DataIngestionModule**: 负责共享文件夹监控、Excel 读取（NPOI 库）及数据清洗。
- **CalculationCore**: 封装预警逻辑与补货建议算法。
- **SecurityModule**: 处理基于仓库 ID 的数据过滤逻辑。
- **WebAPI**: 暴露 RESTful 接口。

## 9. 数据模型与数据库设计

### 9.1 候选表/实体

#### 表 1: `Dim_ThresholdConfig` (阈值配置表)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| ConfigID | INTEGER | PK, AutoInc | 自增主键 |
| WarehouseID | TEXT | Index | 仓库唯一标识 |
| TargetType | INTEGER | 1:SKU, 2:Category | 配置粒度 |
| TargetValue | TEXT | Index | SKU 编码或分类名称 |
| ThresholdDays | REAL | Not Null | 预警天数 X |

#### 表 2: `Fact_InventorySnapshot` (库存快照表 - 由 Excel 导入)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| SKUCode | TEXT | PK | SKU 编码 |
| WarehouseID | TEXT | PK | 仓库 ID |
| CurrentStock | REAL | | 当前库存 |
| InTransitStock | REAL | | 在途库存 |
| AvgDailySales | REAL | | 过去 7 天日均销量 |
| LastUpdateTime | DATETIME | | 数据导入时间 |

### 9.2 关系与约束
- **基数**: 一个仓库对应多个 SKU 配置；一个 SKU 在不同仓库可有不同阈值。
- **一致性**: 每次 Excel 导入时，先清空 `Fact_InventorySnapshot` 对应仓库的数据（全量覆盖更新）。

---

## 10. 关键流程 / 时序说明

### 10.1 数据同步流程
1. **Timer 触发**: 每 4 小时启动。
2. **文件扫描**: 检查共享文件夹中的三个指定 Excel 文件。
3. **解析与校验**: 校验 SKU 编码、仓库 ID 是否存在。
4. **计算**: 计算 `AvgDailySales` 并写入快照表。
5. **完成**: 更新系统状态表中的 `LastSyncTime`。

---

## 11. 安全、隐私与合规

- **数据隔离**: 所有 SQL 查询必须强制包含 `WHERE WarehouseID = @UserWarehouseID`。
- **访问控制**: 前端根据角色隐藏“阈值配置”入口。

---

## 12. 可观测性与运维

- **日志记录**: 记录每次 Excel 解析的行数、成功数、跳过数及跳过原因（如：SKU 缺失）。
- **健康检查**: 若共享文件夹无法访问，需在看板显著位置提示“数据源连接异常”。

---

## 13. 部署与环境规划

- **服务器**: Windows Server (支持 IIS 运行 C# WebAPI)。
- **存储**: 需挂载共享文件夹网络驱动器。
- **数据库**: 应用程序根目录下的 `data.db` (SQLite)。

---

## 14. 测试与验收方案

- **逻辑验证**: 构造 7 天销量为 0 的测试数据，确认其出现在“库存充足”分类中。
- **覆盖验证**: 设置 SKU 级阈值为 10，分类级为 5，确认系统按 10 天进行预警计算。
- **权限验证**: 使用 A 仓库管理员账号登录，确认无法通过 API 获取 B 仓库的明细。

---

## 15. 风险、权衡与假设

- **假设**: 假设 Excel 中的“SKU 编码”和“仓库 ID”在三个文件中完全一致且不为空。
- **风险**: 若 Excel 文件被长期占用（打开状态），可能导致系统读取失败。
- **权衡**: 采用全量覆盖而非增量更新库存快照，以简化逻辑并确保数据一致性。
