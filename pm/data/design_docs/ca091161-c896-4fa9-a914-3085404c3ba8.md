# 系统设计文档

> 该设计文档基于结构化需求生成，旨在指导个人记账本 Demo 的研发落地。
> 收集覆盖率: 89% | 确认完成度: 56%
> 技术栈：Vue + Flask + SQLite

## 1. 范围与目标

- **项目名称**: 个人记账本
- **需求名称**: 基础收支记录与统计系统
- **背景说明**: 开发一个简单的个人记账工具，用于记录日常的财务收支情况。
- **目标**: 帮助用户快速记录每日花费和收入，并自动生成日度和月度的收支统计，实现简单的财务复盘。

### 1.1 本次范围（MVP）
- **支出/收入记录**: 支持金额、分类、备注的录入。
- **分类管理**: 用户可自定义分类名称（增、改）。
- **自动化统计**: 系统自动计算当日及当月的收支汇总。
- **本地存储**: 数据持久化存储于本地数据库。

### 1.2 非本次范围
- 多账户管理（如现金、银行卡、支付宝余额追踪）。
- 用户登录与云端同步（纯本地单机版）。
- 历史日期补记（系统强制记录为当前操作日期）。

## 2. 用户角色与参与方

- **个人用户**: 系统的唯一使用者，负责录入数据并查看统计结果。

## 3. 系统用例

### 3.1 用例 1：记录收支流水
- **参与者**: 个人用户
- **触发条件**: 用户产生消费或获得收入
- **前置条件**: 系统已启动，分类已初始化
- **主流程**:
    1. 用户点击“记账”按钮。
    2. 用户输入金额。
    3. 用户选择收支类型（收入/支出）。
    4. 用户从下拉列表中选择分类。
    5. 用户输入备注（可选）。
    6. 用户点击“保存”。
- **异常流程**: 金额输入非数字或为空，系统提示错误并拒绝保存。
- **后置条件**: 记录存入数据库，流水列表更新。
- **验收检查点**: 记录的日期必须为当前系统日期，金额准确。

### 3.2 用例 2：查看收支统计
- **参与者**: 个人用户
- **触发条件**: 用户进入首页或统计页
- **主流程**:
    1. 系统自动读取当前日期的所有记录并求和。
    2. 系统自动读取当前月份的所有记录并求和。
    3. 页面展示：今日支出/收入、本月支出/收入。
- **验收检查点**: 统计数值应等于明细之和。

### 3.3 用例 3：自定义分类
- **参与者**: 个人用户
- **触发条件**: 用户需要新的分类标签
- **主流程**:
    1. 用户进入“分类管理”页面。
    2. 用户输入新分类名称并选择类型（收入/支出）。
    3. 系统校验名称是否重复。
    4. 系统保存新分类。
- **验收检查点**: 新分类在记账时的下拉列表中可见。

## 4. 功能需求

### 4.1 功能概述
系统核心为基于本地存储的收支流水记录，支持分类自定义及自动化的日/月统计。

### 4.2 功能明细
- **收支录入**: 自动获取 `YYYY-MM-DD` 日期，支持浮点数金额。
- **流水展示**: 按时间倒序排列的简单列表。
- **分类维护**: 提供分类的增加和修改功能。
- **统计看板**: 简单的文字或卡片汇总展示。

### 4.3 业务规则
- **日期锁定**: 账单日期强制为记录时的当前日期，不支持用户手动选择或修改日期。
- **分类唯一性**: 同一收支类型下，分类名称不可重复。

## 5. 非功能需求
- **响应速度**: 本地操作，页面加载与保存操作应在 200ms 内完成。
- **易用性**: 核心记账流程不超过 3 次点击。
- **持久性**: 程序关闭后数据不丢失（SQLite 实现）。

## 6. 高层架构设计
采用简单的单体前后端分离结构：
- **前端 (Vue)**: 负责 UI 渲染、用户交互逻辑、数据校验。
- **后端 (Flask)**: 提供 RESTful API，处理业务逻辑，操作数据库。
- **数据库 (SQLite)**: 单文件数据库，存储于本地。

## 7. 模块职责划分

| 模块 | 职责 |
| :--- | :--- |
| **Frontend (Vue)** | 视图层：记账表单、流水列表、统计卡片、分类设置。 |
| **Backend (Flask)** | 逻辑层：接收请求、计算统计数据、执行 CRUD 操作。 |
| **Storage (SQLite)** | 数据层：持久化存储 `records` 和 `categories` 表。 |

## 8. API 设计（草案）

| 接口路径 | 方法 | 说明 |
| :--- | :--- | :--- |
| `/api/records` | GET | 获取流水列表（支持按月筛选 TBD） |
| `/api/records` | POST | 新增一条账单记录 |
| `/api/categories` | GET | 获取所有分类 |
| `/api/categories` | POST | 新增分类 |
| `/api/stats/summary` | GET | 获取今日及本月汇总数据 |

## 9. 数据模型与数据库设计

### 9.1 数据库表设计 (SQLite)

#### 表 1: `categories` (分类表)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | INTEGER | PK, AI | 分类 ID |
| name | TEXT | NOT NULL | 分类名称 |
| type | TEXT | NOT NULL | 类型：'income' 或 'expense' |

#### 表 2: `records` (账单记录表)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | INTEGER | PK, AI | 记录 ID |
| amount | REAL | NOT NULL | 金额 |
| category_id | INTEGER | FK (categories.id) | 关联分类 |
| type | TEXT | NOT NULL | 类型：'income' 或 'expense' |
| note | TEXT | - | 备注 |
| created_at | DATE | DEFAULT CURRENT_DATE | 记录日期（不可改） |

### 9.2 数据约束与一致性
- 删除分类时，需检查 `records` 表中是否存在关联数据（建议采用逻辑删除或禁止删除已使用的分类）。

## 10. 关键流程 / 时序说明

### 10.1 记账流程
1. 用户在 Vue 界面输入数据。
2. Vue 调用 `POST /api/records`。
3. Flask 校验数据合法性。
4. Flask 插入数据至 SQLite，`created_at` 使用数据库默认值。
5. 返回成功，Vue 刷新列表和统计数据。

## 11. 安全、隐私与合规
- **数据隐私**: 数据仅存储在用户本地设备，不上传至任何服务器。
- **安全**: 虽无登录，但建议对数据库文件进行基础权限保护。

## 12. 可观测性与运维
- **日志**: Flask 记录基础的操作日志（如：`INFO: Record added - 50.00`）。
- **错误处理**: 前端捕获 API 异常并弹出 Toast 提示。

# 13. 部署与环境规划
- **开发环境**: Python 3.x + Node.js。
- **生产环境 (Demo)**: 
  - 后端：Flask 运行在本地 `127.0.0.1:5000`。
  - 前端：Vue 构建静态文件，可通过 Nginx 或 Flask 静态目录托管。

## 14. 测试与验收方案
- **功能测试**: 验证收支保存、分类新增、统计数值准确性。
- **边界测试**: 输入 0 元、超大金额、特殊字符备注。
- **验收点**: 确保日期字段在数据库中自动生成且无法通过 API 修改。

## 15. 风险、权衡与假设
- **风险**: 日期不可修改意味着用户无法补记昨天的账单，可能导致用户流失。
- **权衡**: 为了保持 Demo 的极简性，牺牲了补记功能。
- **假设**: 假设用户单机使用，不考虑多端同步冲突。
