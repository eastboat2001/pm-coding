# 系统设计文档

> 该设计文档基于结构化需求生成，旨在指导开发人员使用原生技术栈实现个人备忘录日历。
> 收集覆盖率: 100% | 确认完成度: 100%

## 1. 范围与目标

- **项目名称**: 个人备忘录日历
- **需求名称**: 纯静态网页日历备忘录需求规格说明
- **背景说明**: 开发一个基于纯静态网页的个人日历工具，允许用户在本地浏览器中记录和管理每日备忘信息。
- **目标**: 提供一个无需后端支持、轻量级且数据持久化的个人办公辅助工具。

### 1.1 本次范围
- PC端原生 HTML/CSS/JS 开发（不使用 Vue/React 等框架）。
- 使用浏览器 `LocalStorage` 进行本地数据持久化。
- 日历按月展示，每周以**周一**为起始。
- 提供年份（当前前后10年）与月份下拉框快速导航。
- 备忘录的增删改功能（通过 Modal 弹窗实现）。
- 视觉标记：有内容的日期背景色变色，“今天”特殊高亮。

### 1.2 非本次范围
- 后端服务器及数据库集成。
- 移动端响应式深度适配（优先保证 PC 端体验）。
- 多端数据同步（数据仅保留在当前浏览器）。

## 2. 用户角色与参与方
- **PC端办公用户**: 在电脑浏览器上记录每日工作计划或备忘。
- **个人用户**: 需要简单、隐私（数据不上传）的日程记录工具。

## 3. 系统用例

### 用例 1：查看日历与备注状态
- **参与者**: 用户
- **触发条件**: 页面加载或切换年月
- **前置条件**: 浏览器支持 LocalStorage
- **主流程**:
    1. 系统根据当前选择的年月计算日历网格。
    2. 系统遍历当月每一天，检查 LocalStorage 中是否存在对应 Key。
    3. 若存在内容，该日期格子应用“有内容”的 CSS 类（改变背景色）。
    4. 若日期等于系统当天，应用“今天”的 CSS 类。
- **验收检查点**: 日历排列正确（周一开头），有内容的格子视觉反馈明显。

### 用例 2：编辑/保存备忘录
- **参与者**: 用户
- **触发条件**: 点击日历中的某个日期格子
- **前置条件**: 无
- **主流程**:
    1. 用户点击日期格子。
    2. 系统弹出 Modal 弹窗，显示该日期标题。
    3. 系统从 LocalStorage 读取该日期旧内容并填充到多行文本框。
    4. 用户输入/修改文字后点击“保存”。
    5. 系统将内容写入 LocalStorage，关闭弹窗并刷新该格子背景色。
- **验收检查点**: 弹窗内容回显准确，保存后页面不刷新即可看到背景色变化。

### 用例 3：清空备忘录
- **参与者**: 用户
- **触发条件**: 在编辑弹窗中点击“删除/清空”按钮
- **主流程**:
    1. 用户打开已有内容的日期弹窗。
    2. 点击“删除/清空”按钮。
    3. 系统从 LocalStorage 中移除该日期的 Key。
    4. 关闭弹窗，该日期格子恢复默认背景色。
- **验收检查点**: LocalStorage 中对应数据被移除，视觉标记消失。

## 4. 功能需求

### 4.1 功能明细
- **日历渲染引擎**: 纯 JS 实现，处理每月天数、闰年及周一偏移量。
- **年月导航**: 动态生成年份下拉项（当前年 ±10年），月份 1-12 月。
- **“回到今天”**: 一键重置年月下拉框至当前系统时间并重绘日历。
- **Modal 交互**: 原生 JS 控制 CSS 显示/隐藏，阻止背景滚动。
- **数据持久化**: 封装 LocalStorage 的读、写、删操作。

### 4.2 业务规则
- **周起始日**: 必须为周一。
- **数据 Key 格式**: 统一使用 `memo_YYYY-MM-DD`（例如 `memo_2023-10-27`）。
- **视觉区分**: 
    - “今天”：建议使用深色边框或主题色文字。
    - “有内容”：建议使用浅蓝色或黄色背景。

## 5. 非功能需求
- **性能**: 页面加载及日历切换响应时间 < 100ms。
- **兼容性**: 适配 Chrome, Edge, Safari, Firefox 最新版本。
- **易用性**: 弹窗需支持点击遮罩层关闭或 ESC 键关闭（可选）。
- **隐私**: 所有数据仅存储在用户本地，不进行网络传输。

## 6. 高层架构设计
采用**单体静态结构**：
- `index.html`: 页面结构与 Modal 结构。
- `style.css`: 布局（Grid/Flexbox）与视觉样式。
- `script.js`: 业务逻辑、DOM 操作与数据管理。

## 7. 模块职责划分
- **Calendar Core**: 负责日期计算、生成日期数组。
- **UI Renderer**: 负责根据日期数组生成 HTML 字符串并插入 DOM，处理 CSS 类切换。
- **Storage Manager**: 负责与 `window.localStorage` 交互。
- **Event Handler**: 负责监听下拉框改变、点击日期、点击按钮等事件。

## 8. API 设计（内部 JS 函数）
由于是纯前端项目，此处定义关键逻辑函数：
- `renderCalendar(year, month)`: 核心渲染函数。
- `getMemo(dateStr)`: 获取指定日期的备忘。
- `saveMemo(dateStr, text)`: 保存备忘。
- `deleteMemo(dateStr)`: 删除备忘。
- `initYearDropdown()`: 初始化年份下拉框。

## 9. 数据模型与数据库设计

### 9.1 存储方案
使用浏览器 **LocalStorage**。

### 9.2 数据结构
| Key (String) | Value (String) | 用途 |
| :--- | :--- | :--- |
| `memo_YYYY-MM-DD` | 纯文本字符串 | 存储具体日期的备忘录内容 |

### 9.3 数据约束
- **Key 唯一性**: 每个日期仅对应一个 Key。
- **容量限制**: 遵循浏览器限制（通常 5MB），对纯文本而言几乎无限。

## 10. 关键流程 / 时序说明
1. **初始化流程**: 页面 Load -> 获取当前系统年月 -> `initYearDropdown()` -> `renderCalendar()`。
2. **更新流程**: 用户切换下拉框 -> 获取新年月 -> `renderCalendar()`。
3. **保存流程**: 点击保存 -> `localStorage.setItem()` -> `renderCalendar()` (局部或全局重绘以更新背景色)。

## 11. 安全、隐私与合规
- **数据隐私**: 数据完全保留在本地，符合极高隐私要求。
- **输入安全**: 在将 LocalStorage 内容插入 DOM 时，使用 `textContent` 或进行 HTML 转义，防止 XSS 攻击。

## 12. 可观测性与运维
- **日志**: 关键操作（如保存失败）通过 `console.error` 输出。
- **版本管理**: 建议在代码头部标注版本号。

## 13. 部署与环境规划
- **开发环境**: 本地任意编辑器（VS Code 等）。
- **部署**: 
    - 直接双击 `index.html` 运行。
    - 或托管至 GitHub Pages / Vercel 等静态托管平台。

## 14. 测试与验收方案
- **逻辑测试**: 切换到 2024 年 2 月，确认有 29 天。
- **排列测试**: 确认每月 1 号对应的星期几是否正确，且第一列为周一。
- **持久化测试**: 输入内容保存后，关闭浏览器重新打开，内容应依然存在。
- **边界测试**: 检查年份下拉框的最早和最晚年份。

## 15. 风险、权衡与假设
- **风险**: 用户清理浏览器缓存/插件可能会导致 LocalStorage 数据丢失。
- **权衡**: 放弃了 Vue 等框架以换取零依赖和极速加载，但增加了手动 DOM 操作的复杂度。
- **假设**: 假设用户使用的是支持 HTML5 的现代浏览器。
