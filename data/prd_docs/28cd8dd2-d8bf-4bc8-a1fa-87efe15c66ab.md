## 2. 需求背景

### 2.1 背景说明
用户需要一个在本地环境或私有服务器运行的轻量化工具，用于管理个人题库并进行自测练习。目前缺乏一个简单、无广告、支持自定义导入且能记录详细练习历史的个人自测工具。

### 2.2 需求目标
- 提供便捷的题库导入与在线维护能力。
- 实现灵活的随机抽题自测模式。
- 支持答题进度保护，防止意外关闭导致数据丢失。
- 记录完整的练习历史，便于复盘。

## 3. 需求范围

### 3.1 本次范围
- **题库管理**：支持 Excel/JSON 追加导入（带查重）、网页端增删改。
- **自测功能**：按科目/数量随机抽题、正向计时、逐题展示、允许回改。
- **进度保护**：支持刷新或关闭页面后恢复答题进度。
- **阅卷回溯**：自动阅卷（每题 1 分）、保存并查看包含每题作答详情的历史记录。
- **技术栈**：Vue + Flask + SQLite，单机/私有化部署。

### 3.2 非本次范围
- 不支持多选题、判断题、填空题等非单选题型。
- 不支持题目中包含图片、公式或复杂富文本。
- 不涉及用户登录、注册及多用户权限管理。
- 不涉及自动汇总错题的“错题本”功能。

## 4. 用户与使用场景

### 4.1 目标用户
- 需要进行题目自测练习的个人学习者。

### 4.2 核心使用场景
1. **题库构建**：用户准备好 Excel 题目，上传至系统，系统自动过滤重复题目并存入对应科目。
2. **随机自测**：用户选择“英语”科目，设定“20题”，系统随机出题并开始计时。
3. **意外中断**：用户在答题时浏览器崩溃，重新打开页面后，系统提示并恢复到刚才的题目和计时状态。
4. **结果复盘**：测试完成后，用户查看总分，并逐一点击题目查看自己当时的选项与正确答案、解析。

## 5. 功能需求

## 5.1 功能概述
系统通过“导入/管理-配置抽题-计时答题-自动阅卷-历史追溯”的闭环逻辑，满足个人自测需求。

### 5.2 功能点明细

#### 功能点 1：题库导入
- **功能描述**：通过文件批量增加题目。
- **触发方式**：用户在管理页点击“导入”并上传文件。
- **处理逻辑**：
    1. 解析 Excel/JSON。
    2. **查重规则**：若“题目内容”与库中已有记录完全一致，则跳过该行。
    3. **追加模式**：非重复题目直接写入数据库。
- **输入项**：Excel/JSON 文件（含科目、题目、选项A-D、答案、解析）。
- **输出结果**：导入汇总报告（成功 X 条，跳过 Y 条）。

#### 功能点 2：随机抽题自测
- **功能描述**：根据用户需求生成临时试卷。
- **触发方式**：用户在配置页点击“开始测试”。
- **处理逻辑**：从选定科目中随机抽取指定数量的题目。
- **输入项**：科目（下拉选择）、题目数量（输入框）。
- **输出结果**：进入答题界面。

#### 功能点 3：计时答题与进度恢复
- **功能描述**：逐题答题，记录耗时，支持断点续做。
- **触发方式**：进入答题页自动触发。
- **处理逻辑**：
    1. **展示**：一次仅显示一题，提供“上一题”、“下一题”按钮。
    2. **计时**：前端开启正向计时器。
    3. **持久化（假设）**：用户每选一个选项，系统实时将当前进度（题号、已选答案、当前耗时）同步至后端或 LocalStorage。
- **异常情况**：页面刷新或关闭后，重新进入系统应弹出“恢复进度”提示。

#### 功能点 4：阅卷与历史详情
- **功能描述**：交卷后计算成绩并存档。
- **处理逻辑**：对比用户答案与标准答案，每题 1 分，计算总分并记录结束时间。
- **输出结果**：展示得分、总耗时、题目列表（标记对错）。点击题目可看解析。

## 6. 业务规则
- **科目关系**：一个题目仅属于一个科目（1对1）。
- **选项限制**：单选题固定为 4 个选项（A, B, C, D）。
- **计分规则**：每题固定 1 分，不设权重。
- **修改规则**：在点击“提交试卷”前，允许用户返回之前的题目修改答案。
- **内容格式**：仅支持纯文本，不支持 HTML 标签。

## 7. 页面/交互说明

### 7.1 页面说明
- **题库管理页**：展示题目列表，支持按科目筛选，提供导入、新增、编辑、删除入口。
- **自测配置页**：简单的表单页，选择科目和题目数。
- **答题练习页**：上方显示进度条和计时器，中间显示题干和 A/B/C/D 选项，下方为导航按钮。
- **历史记录页**：列表展示历次测试的日期、科目、得分、耗时。

### 7.2 交互流程
1. 用户进入管理页 -> 上传 Excel -> 系统反馈导入结果。
2. 用户进入配置页 -> 选科目、填数量 -> 点击开始。
3. 答题页：点击选项 -> 点击下一题 -> ... -> 点击提交 -> 确认弹窗。
4. 结果页：查看分数 -> 点击错题查看解析。

## 8. 文案说明
- **导入反馈**：`“导入完成！成功追加 {count} 道题目，跳过 {skip} 道重复题目。”`
- **交卷确认**：`“确定要交卷吗？交卷后将无法修改答案。”`
- **进度恢复提示**：`“检测到您有未完成的测试，是否恢复到上次答题位置？”`
- **空状态**：`“该科目下暂无题目，请先导入。”`

## 9. 数据与依赖
- **数据库**：使用 SQLite 存储题目表、科目表、测试记录表、答题明细表。
- **文件依赖**：依赖标准 Excel 模板（表头：科目、题目内容、选项A、选项B、选项C、选项D、正确答案、解析）。
- **环境依赖**：需安装 Python (Flask) 及 Node.js (Vue) 运行环境。

## 10. 风险与注意事项
- **排版风险**：若题目文本极长，前端需处理溢出隐藏或滚动，避免撑破布局。
- **数据丢失风险**：由于是本地部署，若用户手动删除 SQLite 数据库文件，数据将无法找回。
- **导入格式风险**：**假设**用户会严格遵守系统提供的 Excel 模板，程序需做基础的字段校验。

## 11. 验收标准
- [ ] 能够成功导入包含 100 条题目的 Excel 文件，且重复题目被正确跳过。
- [ ] 随机抽题数量与用户设定一致，且题目不重复。
- [ ] 答题中途刷新浏览器，重新进入后能恢复已选答案和计时。
- [ ] 提交后得分计算准确（正确数 = 分数）。
- [ ] 历史记录中能完整回溯某次测试每一题的作答情况。
